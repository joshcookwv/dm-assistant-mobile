*This report covers two testing passes on the same sideloaded build. The first was a free-tier pass (screenshots `01_initial.png`–`76_npc3_details.png` and `01-launch.png`–`33-campaign-overview.png`) where no purchase or reviewer code was available. Free-tier findings are preserved unchanged below; everything under "Pro-tier pass" is new.*

## Verdict

Yes, I'd use this at my table, and now that I've actually gotten Pro to work end-to-end, I'd pay for it too. The SRD library and homebrew tools are genuinely solid on the free tier, which is enough to kick the tires before you'd ever need to pay. Pro itself checks out on every feature I could reach: unlimited campaigns is real and unlocks instantly, the encounter tracker and maps feature are both well-built and functional, PDF import demonstrably works (it had already successfully extracted 1 NPC and 1 monster from a real PDF before I even started this pass), and AI credit gating is consistent and crash-free everywhere I poked it. The bestiary bug flagged in the free-tier pass — Acolyte sometimes opening as Aboleth — has since been root-caused and retracted: it was a testing-coordinate mistake (an unscaled screenshot tap landing one row too high), not an app defect; five precise, bounds-verified taps in a row all opened the correct monster. New this pass: a stale-count bug in the Backup & Restore summary caption, and the fact that I could not personally trigger a fresh AI generation to judge output quality firsthand, because the daily credit pool was already exhausted before I ever touched the device today.

## Bugs and issues found

**1. (RETRACTED — testing artifact, not an app bug) Monster detail page opened the wrong monster.** The free-tier pass reported that tapping "Acolyte" in the bestiary sometimes opened the *Aboleth* stat block instead, and flagged it as the top launch-blocking concern. Follow-up investigation (main session, same day) traced this to the QA process itself, not the app: the Acolyte row's exact on-device bounds are `[37,1518]–[1043,1689]` (center y≈1604), directly below Aboleth's `[37,1325]–[1043,1496]` (center y≈1410). Tapping the precise center of the Acolyte row correctly opened Acolyte five times in a row, including two rapid back-and-forth stress tests with ~0.2s between actions. Deliberately tapping an *unscaled* screenshot coordinate (y=1330 — what you'd get from eyeballing Acolyte's position in a 900×2000 displayed screenshot and forgetting to multiply by the 1.2x factor needed to convert to the device's real 1080×2400 pixels) reliably opened Aboleth instead, because that raw coordinate genuinely lands inside Aboleth's row bounds, one row too high. That's the same coordinate-scaling mistake made independently at least twice elsewhere in this same testing effort (including by the main session itself, on an unrelated screen). The list/navigation/data-lookup code (`src/app/monsters/index.tsx`, `src/lib/monsters.ts`, `src/lib/srd.ts`, `src/app/monsters/srd/[key].tsx`) was also reviewed directly: `srdKey` is derived from each SRD entry's own unique `key` field (not by array index), `getSrdEntry` does an exact-match lookup, and there are no key collisions between Aboleth and Acolyte's actual SRD data. **Downgrading this from a launch blocker to a non-issue.** One genuine, unrelated code-quality note found during the review: `src/app/monsters/srd/[key].tsx`'s data-fetching `useEffect` has no stale-request guard (unlike the equivalent list-loading effect in `monsters/index.tsx`, which correctly uses a request-id ref) — not what caused this symptom, and not reproducible, but cheap, standard-pattern insurance worth adding defensively.

**2. (New, Low-Medium) Backup & Restore summary caption is a stale, mount-time snapshot.** After creating my third campaign and second map, I opened Settings and the "Backup ready — N campaigns…" caption read "2 campaigns, 3 NPCs, 1 encounter, **1 map**, 2 homebrew monsters" — undercounting both the campaign I'd just created and the map I'd just added. Leaving Settings and re-entering recomputed it correctly to "3 campaigns… 2 maps." The caption is evidently computed once when the screen mounts rather than reading live state, so it can visibly lag behind what's actually in the app. I could not determine whether this staleness also affected the *actual exported JSON payload* on my first export attempt (vs. only the display caption) — this emulator doesn't have a local-save app in its share sheet, and the app isn't marked debuggable, so I had no way to pull the private backup file's bytes to check. If the underlying export is always current and only the caption lags, this is purely cosmetic. If the export itself can also be stale, that's a real data-integrity risk worth the developer's own direct check with proper tooling. I'm flagging the uncertainty rather than guessing.

**3. (Low, cosmetic) Combatant name "Npc: Wind Acolyte" has inconsistent capitalization.** In the pre-existing encounter, one combatant is labeled "Npc: Wind Acolyte" rather than "NPC: Wind Acolyte." I didn't create this combatant myself so I can't be certain whether it's an app-generated label (worth a capitalization fix) or an artifact of how it was manually typed in an earlier session — flagging it for someone with source access to check quickly.

**4. (Low-Medium, free tier) Duplicate spell search results.** Searching "Fireball" with two sourcebooks selected in the filter returned both Fireball and Delayed Blast Fireball twice each. Most likely the same SRD spell is indexed under two overlapping sourcebook entries.

**5. (Cosmetic, free tier, previously known) NPCs empty-state text is missing a word.** On a fresh NPCs screen with zero NPCs saved, the empty-state heading reads "Your roster is" instead of "Your roster is empty." This matches an earlier verification pass's independent finding.

**6. (Non-issue, free tier, likely a testing artifact) Homebrew form field values briefly landed in the wrong boxes** during the original Silt Maw creation — most likely fat-fingered taps against a cramped keyboard-adjacent layout rather than a data bug. The monster saved with fully correct data in the end.

## What genuinely impressed me

- **Unlimited campaigns just works.** No friction, no re-prompt, no weirdness — tap New Campaign, fill it in, it's there, three campaigns deep with zero degradation.
- **The encounter tracker is a real feature, not a checkbox.** Round/turn tracking, per-combatant HP with live health bars, autosave, initiative ordering, and a genuinely thought-out "Add combatants" flow that pulls from the bestiary or lets you type a custom entry. This is table-ready.
- **PDF import actually works.** This is the Pro feature I was most skeptical would turn out to be vaporware or a thin wrapper, and instead I found hard proof — "Imported 1 NPC, 1 monster, 0 rule notes" — sitting in the app from a real prior run, plus I personally walked the entire file-picker mechanics through with a hand-authored PDF and watched it correctly reach the extraction call before being credit-gated.
- **AI credit gating never breaks anything.** I hit the "Daily AI credit limit reached" wall at least five separate times across three different features this pass, and every single time it was the same clean inline red text with no crash, no frozen button, no confusing partial state. That's the kind of consistency that's easy to get wrong and this app got right.
- **Maps' External Link source type is a smart, low-effort design choice** — most DMs already have their maps somewhere else (Owlbear Rodeo, a Google Drive folder, whatever), and letting the app be a well-organized pointer to that rather than forcing a re-upload is the right call.
- **Export Backup produces a real, timestamped, shareable file through the actual OS share sheet** — not a stub, not a "coming soon," a genuine `campaign-backup-<ISO-timestamp>.json` handed to Quick Share/Drive/Gmail like any other Android share intent.
- No crashes turned up anywhere in this pass, across campaign creation, encounter combat-state changes, map creation, repeated credit-gate hits, and the full PDF-picker round trip.

## UX friction / rough edges

- Duplicate search results when multiple sourcebooks overlap on the same spell — the one standing issue worth a look, since it's a real, reproducible content-indexing overlap (unlike the retracted bestiary-navigation finding above).
- The monster form's combat-stat row is a cramped two-column layout right where the keyboard pops up.
- The NPCs empty-state typo, small as it is, greets every new user.
- New this pass: the Backup & Restore summary caption can visibly undercount your own data if you've added something since Settings was last opened — low-stakes but worth a live-recompute fix so it doesn't accidentally read as "did my last export not include everything?"
- New this pass, and specific to my own automation rather than the app: several "New X" forms (Campaign, NPC, Map) persist an in-progress draft indefinitely and re-populate it the next time you open that form, even after you cancel out. This is likely a deliberate "don't lose my typing" feature, and it's a reasonable one — but it means a DM who cancels out of a half-typed form and comes back later could easily miss that old text is still sitting there and submit something they didn't intend to. Worth a subtle "resuming draft" indicator, or a clear way to discard the draft explicitly.

## Hands-on Pro experience — the honest summary

This is the section this whole pass existed to write, so here it is straight: **every Pro feature I could reach worked as advertised, mechanically.** Unlimited campaigns, the encounter tracker, maps, PDF import's file-picker plumbing, and Export Backup's real file/share-intent flow all held up under direct, hands-on use — not just reading the paywall copy. AI credit gating is rock-solid: consistent, clean, never once broken across five-plus hits.

The one honest gap: **I never got to watch a fresh AI generation happen and judge its output quality with my own eyes**, because the daily credit pool was already fully spent before this pass began — almost certainly by the earlier cut-off session's real (if undocumented) use of the same features I was about to test. What I have instead is strong circumstantial evidence rather than a live result: a specific, well-formed, clearly-not-generic NPC draft ("Grimsby Ironhand," a Dwarf Blacksmith at "Ironhold Forge, Dockside," tagged "ally, quest-giver, merchant") sitting unsaved in the form, and a PDF import that had already concretely and correctly extracted "1 NPC, 1 monster, 0 rule notes" from a real file. Both point toward genuinely useful output, not filler — but I want to be precise about the difference between "I saw evidence this works well" and "I personally triggered it and watched it work well," because those are different claims and only the app's owner (or a future pass after the credit pool resets) can close that last gap.

## Is Infernal Codex Pro worth it?

Now a real, lived verdict instead of a speculative one. **Yes.** The free plan's single hard limit — one campaign — is real and confirmed gone the instant Pro activates, with zero friction. For a DM running exactly one game, Pro buys an NPC generator, campaign/session AI summaries, and PDF import as genuine nice-to-haves that I've now confirmed actually function rather than just appearing in a feature list. For a DM juggling two or more campaigns, which in my experience is most DMs eventually, Pro is the only way in, and $4.99/month for that plus a shared 10-credit/day AI pool is a fair trade — especially now that I've watched the pool get consumed by real work (a PDF import alone is worth half a day's allowance) rather than treating "10 credits" as an abstract number on a paywall screen.

The genuine caveat, and it's a fair one for a prospective subscriber to weigh: the daily AI allowance is tight enough that heavy prep sessions (importing a sourcebook PDF, generating a few NPCs, and summarizing a campaign in the same sitting) could plausibly burn through it before you're done, same as happened here. That's not a bug — it's a real constraint of the pricing tier, and DMs who prep in big batches rather than steady daily use should know that going in.
